Groundedehs-human-factors-ontologyCrosswalkSuggester

From incident narrative to candidate PIFs, with the rule shown

A keyword and phrase matcher. No machine learning. Each suggestion names the rule that fired, the words it matched, and the crosswalk alignment the rule is traced to. It is a prompt for a human coder, not a coding.

Read the result with this in mind. The test text is the set of quoted CSB passages that the 25 gold codings were made from, across 10 investigations and 9 PIFs. Recall therefore measures vocabulary overlap with text a coder already marked, not discovery in unseen narratives. The curated rules were written after reading those quotes, so their numbers are optimistic resubstitution. Precision is against an incomplete gold standard. With this n, one pair moves a PIF's score by 20 to 100 points. None of this estimates performance on other incidents.

How the rules are traced

Each row of crosswalk/pif_rules.csv gives a phrase, a PIF, and an external factor (SPAR-H, CREAM, HFACS or HSE) that the ontology aligns to that PIF; a test fails if the alignment does not exist. A hit therefore unwinds as phrase, PIF, external factor, citation. A trailing * matches any word ending. The baseline rule set is derived by code from the ontology's own labels, with no choice made by hand.

python3 -m ehs_hfo suggest narrative.txt
python3 -m ehs_hfo suggest narrative.txt --json
python3 -m ehs_hfo suggest narrative.txt --rules baseline
python3 tools/evaluate_suggester.py --write

What would make it a real test

Narratives that were not used to build the gold codings, coded by someone other than the rule author, with rules frozen before the test text is read. That needs more coded incidents than the repository has.
